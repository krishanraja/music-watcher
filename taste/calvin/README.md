# Calvin's Music Brain

What Calvin likes, kept separate from Krish's brain (`taste/`). Krish asked for it on 2026-11-15, from Calvin's Spotify
playlist "Fall Bangers" (https://open.spotify.com/playlist/1inChKFsQRxfnGMBagrEib). It works the same way as Krish's brain
(evidence, then recounted patterns, then claims Calvin accepts one by one), with its own graph, claims and approved rules.

| file | what it is |
|---|---|
| `APPROVED.md` | Calvin's approved rules, the only lines a generator or Splice search may follow for Calvin. Generated. |
| `brain/claims.jsonl` | Calvin's proposed, accepted and rejected claims (frozen once proposed). |
| `brain/policy.json` | thresholds (the same as Krish's), whose words count (Calvin's), who decides (Calvin), shared files |
| `brain/PATTERNS.md` | patterns recounted from Calvin's words and Calvin's playlist. Generated. |
| `graph/GENERATION.md` | Calvin's target in numbers, family by family, next to Krish's. Start here to make something. |
| `graph/playlist.json` | the 30 tracks, as read from Spotify's public pages |
| `graph/families.json` | style family per artist (inferred, Claude's read) |
| `graph/graph.json`, `graph/tracks.csv` | the knowledge graph and one row per track. Generated by `build_graph.py`. |

## How it stays separate

- **Words.** Everything Krish or Calvin says about a track still goes in the one shared log, `taste/brain/evidence.jsonl`
  (rules in `AGENTS.md`). Calvin's brain counts only the rows where `"who": "calvin"`. Krish's brain counts both voices, as it
  did before this brain existed. A row is never copied into a second log, and withdrawing a row withdraws it from both brains.
- **Vocabulary.** The shared `taste/brain/vocab.json`; it grows only by a change Krish merges.
- **Measurements.** Calvin's own playlist graph, `graph/tracks.csv`, plus the tracks Calvin drops into Drive's Music
  Production › Inspiration folder (`engine/references/calvin/tracks.csv`, measured by the production engine and read through
  `measured_extra` in `brain/policy.json`; a track already in the playlist counts once). Krish's playlist and drops do not
  count here, and Calvin's do not count in Krish's brain.
- **Decisions.** Calvin accepts or rejects Calvin's claims. Whoever runs the command records Calvin's decision; nobody decides
  in Calvin's place. A rule accepted in one brain is not a rule in the other: Krish accepted "chopped vocals" on Calvin's
  words, and here the same words make a separate claim that waits for Calvin.

## Commands

Every brain command takes `--taste taste/calvin`; without it, the command acts on Krish's brain.

```bash
trackcard brain check   --taste taste/calvin                   # evidence valid?
trackcard brain propose --taste taste/calvin                   # this week's proposals (at most 3, frozen)
trackcard brain accept vocal.vocal_chops --taste taste/calvin  # on Calvin's word
trackcard brain reject groove.tempo_126_plus --taste taste/calvin --why "Calvin's words"
trackcard brain render  --taste taste/calvin                   # rewrite APPROVED.md and brain/PATTERNS.md
python taste/graph/build_graph.py <cards dir> --graph taste/calvin/graph   # rebuild the graph, then render
```

## How it was built

- Track list and lengths: the playlist's Spotify embed page. Release date and album: each track's link-preview page. Label:
  the ℗ line on each album page, rendered in a headless browser. Added dates: the playlist data Spotify's public web player
  loads. No Spotify login or API key was used.
- Audio: SoundCloud through yt-dlp (`content-watch fetch` returned no media for SoundCloud links on the worker), the same
  route as the Music Inspo watcher. Search hits were kept only within 6 s of Spotify's length. Then each file was checked for
  the right recording: the normalised cross-correlation of Spotify's preview against the file was 0.90 to 0.99 for the 18
  accepted and 0.01 to 0.19 for every wrong upload tried. Audio stays in `~/media` on the worker and is never committed.
- Measurement: `trackcard analyze <wav> --json --no-stems --sections laplacian`, the same settings as Krish's graph, so the
  two graphs compare like for like.
- Families: Claude's read. Families that Krish's graph also has keep his definitions; two are new (`families.json`).
